main 场景「开始游戏」按钮 接入报告

工程：Unity6000_打个毛线_Rope  ·  2026-09-19  ·  Unity 6000.2.15f1 / 抖音小游戏

一句话结论

main.unity 里那个 paly 按钮原本 OnClick 完全是空的（0 条绑定）， 而且按钮文字「开始游戏」用的是内置 Arial（没有汉字字形，所以字是看不见的）。 现已把它接成 点击 → 进入主场景 Gameplay，并把 main 登记为启动场景（Build 索引 0）； 同时关掉了背景的点击接收，保证整屏只有这个按钮能触发。

1. 期望流程

main.unity
标题页
──点击「开始游戏」──▶
Gameplay.unity
主场景（玩法）
──商店──▶
CoinShop.unity
金币商店

点背景、点面板、点其它地方都不会有任何反应；只有按钮生效。

2. 改了哪些文件

文件类型说明
Assets/MyAssets/Scripts/MainMenuController.cs 新增 标题页控制器。StartGame() 进入 Gameplay；带运行时兜底：只要 main 被加载就检查按钮绑定，没绑定就自动接上，并防连点。
Assets/MyAssets/Editor/MainSceneSetup.cs 新增 编辑器工具。用 Unity API 改场景（不手写 YAML）：登记 Build 顺序、给 Canvas 挂控制器、把 paly 的 OnClick 指向 StartGame、换中文字体、关背景 Raycast。切回 Unity 自动执行一次，也可手动跑菜单。
Assets/MyAssets/Scripts/GameManager.cs 修改 把写死的 LoadScene(0) 全部改成按场景名加载，并给 OpenScene(int) 加了「序号→场景名」映射。
Assets/MyAssets/Scripts/IAPShopManager.cs 修改 商店「主页」按钮不再按索引跳（索引语义已变），改为按场景名跳 main；并对 AudioManager/AdsManager 加了空判断防 NRE。
刻意没有手改 main.unity 的 YAML。 上次中文化就是因为用脚本直接改场景 YAML、把 m_Font 的缩进写错层级，导致 Unity 反序列化失败、16 个 Text 组件被重置。 这次改成让 Unity 自己改自己存，从根上避开这类问题。

3. 三个必须一起处理的连带问题

3.1 main 必须是启动场景，但写死的 LoadScene(0) 会全部错位

原本 Build 顺序是 Gameplay(0) → CoinShop(1)，代码里一堆地方直接写 SceneManager.LoadScene(0)。 一旦 main 插到索引 0，这些调用全部会跳到标题页——最明显的就是「下一关」会直接跳回菜单。

原调用语义改成
Next() → LoadScene(0)下一关LoadScene("Gameplay")
调试键 M / B → LoadScene(0)跳关 / 退关LoadScene("Gameplay")
ResetGame() → LoadScene(0)「更多关卡」面板的「主页」LoadScene("main")
OpenScene(0) / OpenScene(1)重开本关 / 打开商店按 openSceneNames 映射为场景名
IAPShopManager.Home(0)商店「主页」LoadScene("main")

改完之后场景跳转与 Build Settings 顺序解耦，以后再调整顺序也不会跳错。

3.2 按钮文字看不见

按钮的 Text (Legacy) 引用的是内置 Arial（fileID: 10102），Arial 没有汉字字形， 所以 m_Text 里虽然是「开始游戏」，屏幕上却是空白。工具会把它换成 DroidSansFallback.ttf（guid 4b55cb2d…，和 Gameplay/CoinShop 用的是同一个）， 已确认该字体子集里「开始游戏」四个字全部命中。

3.3 「只有点按钮才生效」

标题页的 /Canvas/Panel 和 /Canvas/Panel/bg 是铺满全屏的 Image， 本来 Raycast Target 是开的。工具会把它们的 Raycast Target 关掉， 这样整屏只有按钮能接收点击，其它位置点下去没有任何反应。

/Canvas/Panel/cebianIcon（侧边栏图标）刻意没动——它以后多半要挂「打开抖音侧边栏」的按钮， 现在把 Raycast 关掉会挡住后路。

4. 双保险机制

层级作用
编辑器层
MainSceneSetup		 把 StartGame 正式写进按钮的 OnClick（Inspector 里看得见、可改），登记 Build 顺序，换字体，关 Raycast。
运行时层
MainMenuController		 [RuntimeInitializeOnLoadMethod] 兜底：main 场景一加载就检查按钮有没有绑定，没有就自动接上。 即使 OnClick 被误清空，按钮依然能用（已做幂等判断，不会和 Inspector 的绑定重复触发）。

5. 验证步骤

  1. 切回 Unity 窗口 → 等编译完成（会自动执行一次设置）。
  2. Console 搜 [主菜单]，应看到类似： 
    [主菜单] 已在 /Canvas 上挂载 MainMenuController
[主菜单] 已把 /Canvas/Panel/paly 的 OnClick 指向 StartGame
[主菜单] 字体 /Canvas/Panel/paly/Text (Legacy) : Arial -> DroidSansFallback
[主菜单] 关闭 Raycast Target: /Canvas/Panel
[主菜单] 关闭 Raycast Target: /Canvas/Panel/bg
[主菜单] main 场景设置完成，共修改 5 处（自动）
    没动静就按 Ctrl+R，或手动执行菜单 Tools ▸ 打个毛线 ▸ 设置开始场景并接好「开始游戏」按钮。
  3. 菜单 Tools ▸ 打个毛线 ▸ 检查 main 场景状态，确认 Build 顺序为 [0] main / [1] Gameplay / [2] CoinShop，按钮持久绑定数 = 1，字体 = DroidSansFallback。
  4. 打开 main.unity 进 Play：点「开始游戏」→ 应进入 Gameplay 并显示「第 N 关」；点背景/空白处 → 无反应。
在设置跑完之前，不要在编辑器里手动保存 main.unity， 也不要手改它的按钮文案——会和自动设置抢同一份数据。

7. 顺带发现（没动，供你决定）

  • main 场景的 CanvasScaler 是 ConstantPixelSize（UiScaleMode = 0，ScaleFactor = 1）。 按钮固定 257×172 像素，在高分屏手机上会显得偏小。想按屏幕自适应，建议改成 Scale With Screen Size + 参考分辨率（例如 1080×1920）。
  • /Canvas/Panel/cebianIcon 没有 Button 组件，目前只是个纯图标。 如果打算做抖音侧边栏入口，需要自己加 Button 并调 AdsManager.ShowSidebar()。
  • GameManager 里仍有 P 重置存档、M 跳 20 关、B 退关、R 重开等调试键， 正式包建议去掉或加 #if UNITY_EDITOR。

8. 回滚

本次没有改动任何 .unity / .meta / 字体文件，场景改动由编辑器工具完成、可逆：

  • 场景层面：在 main 场景里删掉 Canvas 上的 MainMenuController、清空 paly 的 OnClick 即可复原；
  • Build 顺序：Project Settings ▸ Scenes In Build 里把 Gameplay 拖回第一位；
  • 代码层面：GameManager.cs / IAPShopManager.cs 的改动都是「索引 → 场景名」的等价替换，改回 LoadScene(0) 即恢复原状；
  • 新增的两个 .cs 直接删除不影响其它功能（Editor 工具删掉后场景设置就停在那次执行的结果上）。
