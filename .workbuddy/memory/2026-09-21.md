## 修复「TTSDK 构建失败：Failed to activate emscripten glx」

用户截图：TTSDK Unity 调试工具点构建 → Console 报
`Exception occurred during BuildPlayer: Failed to activate emscripten glx`。

### 根因（两条并存，第二条不修会接着失败）

**① GLX 没有匹配当前 Unity 版本的库（直接原因）**

Editor.log 调用链锁定位置：

```
Exception: Failed to activate emscripten glx
  at TTSDKBase.Tool.BuildPlatformWebGL.InitializeBeforeBuildPlayer (BuildContext) [0x00046]
  at TTSDKBase.Tool.Builder.DoBuild (...)
 ← TTSDKBase.Tool.NativePluginManager:SetEmscriptenGlxCompatibility (...)
 ← TTSDKBase.Tool.NativePluginManager:ProcessEmscriptenGlxLib (bool)
```

Console 顺序：`build begin` → 三次 `Disable EmscriptenGLX importer path`
（`libemscriptenglx_3_1_39.a` / `libemscriptenglx.a` / `libemscriptenglx_2021.a`）
→ `EmscriptenGLX plugin not supported for current Unity version` → 抛异常 → `build failed`。

TTSDK 6.9.4 只带 3 个预编译 GLX 库（2021 / 2022-emscripten3.1.39 / 默认），
**Unity 6000.2.15f1 不在名单内** → 工具把候选全部 Disable 后不降级、直接抛异常。
GLX 是 6.9.2 才上线的**可选**优化：`TTSDK.jslib`/`JSB.jslib`/`TTUNBridge.jslib` 里
**无 glx 硬引用**，模板 JS 也是 `!!Module['_glx_init']` 条件判断 → 关掉不影响玩法与上架。

**② `isWebGL2: 0` 与 Unity 6 冲突（紧随其后的第二个坑）**

**Unity 6 起只支持 WebGL 2.0**（官方文档：*"Unity no longer provides support for WebGL 1 in builds
created with the Auto Graphics API option"*）。而 TTSDK 会按 `StarkBuilderSetting.isWebGL2`
覆盖 PlayerSettings 的 Graphics API（技能 Fix 5 已实测），`0` 会让它把 WebGL 设回 1.0。

⚠ 注意：本工程 `m_ActiveColorSpace: 0`（**Gamma**），所以**不会**报技能 Fix 5 那个
`Incompatible color space` —— 别因为看不到那条报错就以为 WebGL2 无关。两个坑独立。

### 已修（改 `Assets/Editor/StarkBuilderSetting.asset`）

| 字段 | 改前 | 改后 | 原因 |
|---|---|---|---|
| `enableEmscriptenGlx` | 1 | **0** | Unity 6 无匹配 GLX 库，工具会抛异常中断构建 |
| `isWebGL2` | 0 | **1** | Unity 6 只支持 WebGL 2.0 |

- 备份：`…\_RopeGlx_Backup_20260921_103834\StarkBuilderSetting.asset`
- 复验：改后 Unity **确实重新导入**了该 asset
  （Editor.log 出现新的 `Start importing Assets/Editor/StarkBuilderSetting.asset ...`），
  与 `.meta` / ProjectSettings 不同，**不会被内存静默写回**。
- ⚠ 但**工具窗口内存里可能仍是旧值** → 必须**关闭并重新打开 TTSDK 工具窗口**（或重启 Unity）再点构建。

### 新增兜底工具

`Assets/MyAssets/Editor/RopeTTSDKBuildFix.cs`（已加 UTF-8 BOM，括号配平 32/32、81/81、3/3 通过，

- **DLL 里的日志文案搜不到时，换 UTF-16LE 再搜一遍**：.NET 的字符串字面量在 metadata

  只按 ASCII 搜会漏掉全部提示文案。本机脚本：`rope_glx_dll.py`(ASCII) / `rope_glx_utf16.py`(UTF-16)。
- **Console 截图上的文字不可全信**：本次截图上有一条 `[Builder] Version Not Support for 3.6.8`，
  但在 Editor.log 全文里**搜不到任何 `3.6.8` / `Version Not`**，属误读。
  **以 Editor.log 的原文为准**（`%LOCALAPPDATA%\Unity\Editor\Editor.log`）。
- 判断"某功能能不能安全关掉"：去 jslib / 模板 JS 里搜有没有硬引用，看是不是条件判断。

## 修复「TTSDK 构建失败：No WebGL template selected!」（同日上午第二例）

GLX 修好后用户再构建，报错换成：
```
Exception: No WebGL template selected! Select a template in player settings.
  at UnityEditor.WebGL.WebGlBuildPostprocessor.UpdateHTMLTemplatePath ()
  at UnityEditor.WebGL.WebGlBuildPostprocessor.PostProcess (BuildPostProcessArgs args)
  at UnityEditor.Modules.BeeBuildPostprocessor.PostProcess (...)
  at UnityEditor.BuildPipeline.BuildPlayer (...)
  ← TTSDK.Tool.BuilderWebGL.StarkBuildSettings.BuildPlayer (...)
```
栈里 `/home/bokken/build/output/unity/unity/...` 是 **Unity 自己的源码路径**
→ 说明是 Unity 内置后处理抛的，**不是 TTSDK 的错**，别去翻 SDK 包。

### 重要副产品：这条报错时包体其实已经打好了

Editor.log 上一行就是场景打包结果（**这是本工程第一次拿到真实进包数字**）：
```
Level 0 'Assets/MyAssets/Scene/main.unity'     uses 1.1 MB compressed /  5.8 MB uncompressed.
Level 1 'Assets/MyAssets/Scene/Gameplay.unity' uses 3.1 MB compressed / 21.6 MB uncompressed.
Level 2 'Assets/MyAssets/Scene/CoinShop.unity' uses 0.7 MB compressed /  3.2 MB uncompressed.
Total compressed size 4.9 MB. Total uncompressed size 30.6 MB.
```
即：**场景序列化数据（含 840 个关卡 JSON）压缩后 4.9MB**，
Gameplay.unity 一个就占 21.6MB 未压缩 —— 印证「关卡 JSON 是场景序列化引用、跟着场景进包」。
`webGLCompressionFormat` 现在磁盘上是 `2`（9-19 是 `0`）→ 是 TTSDK 构建时改的，见下。

### 根因

`ProjectSettings/ProjectSettings.asset` 里 `webGLTemplate:` 是**空值**，正常应为 `APPLICATION:Default`。

**对照法确诊（本次最有价值的一步）**：扫本机 `D:\Unity` 下全部 37 个工程的同名字段——
`APPLICATION:Default` 占绝大多数，另有 `APPLICATION:Minimal`(1)、`Builtin:Default`(1)、
`PROJECT:EccentricGamePush`(1，它自带 `Assets/WebGLTemplates/EccentricGamePush/`)。
→ 无自定义模板的工程一律填 **`APPLICATION:Default`**。
本工程 `Assets/WebGLTemplates/` **不存在**，Unity 内置模板目录存在
（`D:\Hub\Editor\6000.2.15f1\Editor\Data\PlaybackEngines\WebGLSupport\BuildTools\WebGLTemplates\Base\{Default,Minimal,PWA,InstantGames}`）。

**排除项**：TTSDK 包里的 `com.bytedance.starksdk/DefaultTemplate/` 是**小游戏**模板
（`game.js`/`game.json`/`project.config.json`），跟 Unity 的 `webGLTemplate` 无关，别混淆。

### 已修

| 改动 | 位置 | 说明 |
|---|---|---|
| `webGLTemplate: APPLICATION:Default` | `ProjectSettings/ProjectSettings.asset` | 直接补，`sleep(6)` 复验未被写回 |
| `PlayerSettings.WebGL.template = "APPLICATION:Default"` | `Editor/RopeTTSDKBuildFix.cs` | 走 Unity API，权威通道 |
| `RopeBuildPreflight : IPreprocessBuildWithReport` | 同上文件内新类 | **构建前兜底** |

- 备份：`…\_RopeTemplate_Backup_20260921_104800\ProjectSettings.asset`
- API 核对：`P:UnityEditor.PlayerSettings.WebGL.template`、`IPreprocessBuildWithReport.OnPreprocessBuild(BuildReport)`、
  `IOrderedCallback.callbackOrder`、`BuildSummary.platform` 全部在 Unity 自带 XML 文档里命中
  （`Editor/Data/Managed/UnityEditor.xml` 与 `UnityEngine/UnityEditor.CoreModule.xml` —— **查 API 的最快通道**）。
- **为什么兜底有效（时序）**：`PostProcess` 在 `BuildPipeline.BuildPlayer` **内部**才跑，那时改设置来不及；
  `OnPreprocessBuild` 在 BuildPlayer 启动后、真正打包前触发，且**晚于** TTSDK 的
  `SetupWebGLBuildSettings` → 我们写的模板值是最终生效的。

### 🆕 重要发现：TTSDK 会在构建时自己改 PlayerSettings

栈里出现 `TTSDK.Tool.Builder:SetupWebGLBuildSettings(StarkBuilderSettings, PlayerSettings)`
→ 所以 **`webGLCompressionFormat` 归 TTSDK 管，不要手改**（9-19 读 `0`、9-21 读 `2` 就是它改的；
TTSDK 用 `StarkBuilderSetting.needCompress`/`compressMethod` 自己做压缩）。
之前"`0` 是开的、别动"那条结论已作废，改为"别动，因为不是我们管的"。
