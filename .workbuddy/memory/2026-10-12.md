## TortoiseGit 推送失败（Invalid username or token）排查与修复

- 现象：TortoiseGit「推送」报
  `remote: Invalid username or token. Password authentication is not supported for Git operations.`，
  但命令行（WorkBuddy PortableGit）推送**成功**。
- 根因：**两套 git 的凭据来源不同**。`credential.helper` 链 = `system: manager`（Git Credential Manager）
  → `global: store`（`~/.git-credentials`）。
  - **TortoiseGit 走 GCM 交互式** → 从 Windows 凭据管理器取到
    `LegacyGeneric:target=git:https://xingrenshun@github.com` 这条**旧失效凭据** → GitHub 拒绝 basic auth。
  - **命令行非交互** → GCM 取不到 → 回落 store 的**有效 token**（`gho_` 前缀、40 位，API `/user` 返回 200）。
- 修复：用有效 token 覆盖凭据管理器里的坏条目 ——
  `printf "protocol=https\nhost=github.com\nusername=<user>\npassword=<token>\n\n" | "C:/Program Files/Git/cmd/git.exe" credential approve`
  → 之后 **manager-only / 完整链 / store 三个来源返回同一个有效 token**，用系统 git 实测推送成功。
- 关键知识点（下次直接用）：
  1. **两套 system config 不是同一份**：Git for Windows 在 `C:\Program Files\Git\etc\gitconfig`；
     WorkBuddy PortableGit 在 `...\WorkBuddy\resources\vendor\PortableGit\etc\gitconfig`。
     **TortoiseGit 用的是系统那套**（`where git` → `C:\Program Files\Git\cmd\git.exe`）。
  2. 查 Windows 凭据：PowerShell `cmdkey /list | Select-String github`。
     ⚠ **cmdkey 只能删/列，不能改密码**；要覆盖只能用 `git credential approve`（或 CredWrite API）。
  3. 判断凭据好坏：`printf "protocol=https\nhost=github.com\n\n" | git credential fill`（脱敏只看
     password 长度/前缀）→ 再 `curl -H "Authorization: Bearer $TOKEN" https://api.github.com/user` 看是否 200。
     有效 PAT/OAuth token = 40 位、`ghp_`/`gho_` 前缀。GitHub 早已禁用密码认证。
  4. 单独测某个 helper：`git -c credential.helper= -c credential.helper=manager credential fill`
     （空值可重置 helper 列表）。
