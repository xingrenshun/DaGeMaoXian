3 · 根因

ProjectSettings/ProjectSettings.asset 里这一行是空的：

  webGLTemplate:            ← 空值，Unity 无从选择模板

正常应该长这样（二选一）：

取值含义模板位置
APPLICATION:Default Unity 内置模板 Editor/Data/PlaybackEngines/WebGLSupport/BuildTools/WebGLTemplates/Base/<名>/
PROJECT:<模板名> 工程自定义模板 Assets/WebGLTemplates/<模板名>/

怎么确诊的：和本机 37 个同类工程做对照

与其猜该填什么，不如看别的工程怎么填。扫 D:\Unity 下所有工程的同一个字段：

webGLTemplate 取值工程数说明
APPLICATION:Default31主流取值
APPLICATION:Minimal1行李箱排序工程
Builtin:Default1WanZhuanFangKuai
PROJECT:EccentricGamePush1律动小猫，它自带 Assets/WebGLTemplates/EccentricGamePush/
(空)1← 本工程（就是问题所在）
?（字段缺失）2老版本 Unity 写的工程

本工程 Assets/WebGLTemplates/ 不存在，Unity 内置模板目录齐全， 所以正确取值只有一个：APPLICATION:Default。

4 · 一个容易混淆的排除项

已排除 TTSDK 包里有个 com.bytedance.starksdk/DefaultTemplate/ 目录，名字很像，但它不是 Unity 模板。 里面装的是小游戏的东西：game.js / game.json / project.config.json / backgroundportrait.png…… 那是 TTSDK 用来生成 tt-minigame 输出包的， 和 webGLTemplate 完全无关。

Unity 的模板只认两个地方：内置 WebGLTemplates\Base\*，或工程内 Assets/WebGLTemplates/<名>/。

5 · 做了哪三处修改

#改动位置作用
1 webGLTemplate: APPLICATION:Default ProjectSettings/ProjectSettings.asset 直接补上，立刻生效
2 PlayerSettings.WebGL.template = "APPLICATION:Default" Assets/MyAssets/Editor/RopeTTSDKBuildFix.cs 走 Unity API 的权威通道，避免被内存旧值写回
3 RopeBuildPreflight : IPreprocessBuildWithReport 同上文件内新增类 构建前兜底：每次构建前自动校正模板

为什么兜底（第 3 条）才是关键

报错点在 WebGlBuildPostprocessor.PostProcess，它是在 BuildPipeline.BuildPlayer 内部才执行的——那时候再改设置已经来不及。

而 IPreprocessBuildWithReport.OnPreprocessBuild 的时机正好在 BuildPlayer 启动之后、真正打包之前。更巧的是，TTSDK 自己也会在构建前改一批 PlayerSettings：

// 日志堆栈里可见：
TTSDK.Tool.Builder:SetupWebGLBuildSettings (StarkBuilderSettings, PlayerSettings)
TTSDK.Tool.Builder:BuildWebGL (...)
TTSDK.Tool.StarkBuilder:Build (...)

它跑在 BuildPlayer 之前；我们的 preflight 跑在 之后—— 所以最终生效的模板值是我们写的那一个。这个顺序正是这条兜底有效的原因。

6 · 顺带发现：TTSDK 会自己改 PlayerSettings

结论修正 之前我们记的是「webGLCompressionFormat: 0 是开的，别乱动」。 但现在磁盘上它已经是 2 了（9-19 读到 0，9-21 读到 2）。

原因就在上面那个 SetupWebGLBuildSettings —— 它是 TTSDK 在构建时改的。 TTSDK 用 StarkBuilderSetting.needCompress / compressMethod 自己做压缩， 所以 Unity 这侧的值不用我们操心。

新结论：这个字段归 TTSDK 管，不要手改。（既不要"以为没开压缩去打开"，也不要"以为开着重置成 Disabled"。）

7 · 你要做的（1 步）

切回 Unity 窗口，等它编译完（检测到新脚本 → 域重载 → 自动校验一次设置）， 然后回 TTSDK 工具窗口点构建。

Console 里搜 [TTSDK构建修复]，应该看到其中一种：

[TTSDK构建修复] 已修正 1 项设置（自动）。现在可以回到 TTSDK 工具窗口重新点击构建。
或
[TTSDK构建修复] 构建设置已是正确值，无需改动（自动）。

没动静按 Ctrl+R；也可手动跑菜单 Tools ▸ 打个毛线 ▸ 修复 TTSDK 构建设置（Unity 6）， 另有 检查 TTSDK 构建设置 可以核对三个值的现状。

构建真正开始后，如果模板仍有问题，你会看到这条日志（说明兜底生效了）：

[TTSDK构建修复] 构建前已把 WebGL 模板由 "" 修正为 "APPLICATION:Default"
