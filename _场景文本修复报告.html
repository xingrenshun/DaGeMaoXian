场景文本丢失 · 事故定位与修复

工程：Unity6000_打个毛线_Rope · Unity 6000.2.15f1 · 2026-09-19
已定位并修复。 这不是 Unity 的问题，也不是资源丢失 —— 是我 9-18 那次中文化的脚本 把场景 YAML 的字段缩进写坏了，导致 16 个 UI.Text 组件被 Unity 整体重置成默认值， 文案随之清空。原始数据已从备份完整恢复，修复通道也从「改 YAML」换成了「编辑器内脚本」。

关键那一行，m_Font 本应是 m_FontData 的子键（缩进 4），却被写到了行首：

  m_FontData:
m_Font: {fileID: 12800000, guid: 4b55cb..., type: 3}   ← 缩进 0，层级断了
    m_FontSize: 73
    m_FontStyle: 1

组件被重置成什么样（同一组件，左为原始、右为损坏后）：

m_Alignment4（居中）0（左上）
铁证：20 个 Text 组件里，凡是我改过的 16 个全废，没改过的 4 个（00 / +1500 / -150 / 0）完好无损。 规律完全对应，不存在别的原因。

二、修复方式（换了通道）

不再手写 YAML，改成让 Unity 自己改自己存 —— 新增 Assets/MyAssets/Editor/RopeUITextRestore.cs：

数据来源
_RopeScene_Backup_20260919_110241\Gameplay.unity（未损坏的原始版本）
匹配方式
组件 fileID（GlobalObjectId.targetObjectId）+ Transform 层级路径，双键
恢复内容
字体、文案、字号、粗体、对齐、最大字号
触发时机
切回 Unity 重编译完成后自动执行一次（无需点菜单）
手动入口
Tools ▸ 打个毛线 ▸ 修复场景文本（中文化） / 检查场景文本状态
安全性
幂等：只在「字体为空」或「文本为空」时才动；表外的只补字体、不改文案
未打开的场景
以 Additive 方式打开 → 修 → 存 → 关闭，不打扰你正在编辑的场景
独立修复： CoinShop.unity 里 6 行缩进错误的 m_Font 已直接写回（缩进 4）。 全工程扫过 ^(m_Font|m_Text|m_FontSize|m_Alignment|m_MaxSize):，没有其他同类残留。

四、校验做到哪一步

  • 通过 C# 内嵌的 16 条路径 vs 备份真实层级路径，逐字比对 16/16 一致
  • 通过 中文用字 41 个，全部命中 DroidSansFallback 子集（cmap 校验）
  • 通过 API 名称在 UnityEditor.dll 中二进制核对存在（sceneOpened / GlobalObjectId / MarkSceneDirty / SaveScene …）
  • 通过 Editor.log 时序：最后一条 error CS 已早于最后一次重载程序集与字体生成 → 当前工程编译干净
  • 受限 安全策略拦截 csc.exe，无法做单文件编译验证；改用括号配平自检 + 程序集符号核对

五、需要你做的（1 步）

切回 Unity 窗口即可。 它会检测到新脚本 → 重新编译 → 自动执行修复并保存场景。 然后在 Console 里搜 [文本修复]，应看到类似： 
[文本修复] Gameplay  /Canvas/StartPanel/Text (1)  ->  "点击开始"
…
[文本修复] 完成，共处理 16 个 Text 组件（自动）
若显示 0 条，执行菜单 Tools ▸ 打个毛线 ▸ 检查场景文本状态 看是否有「异常」计数。
在修复跑完之前，请不要在编辑器里手动保存 Gameplay 场景，也不要手改它的文案 —— 会与修复脚本抢同一份数据。修复完成后就正常了。
