TTSDK 构建报错修复报告

宥如极速冒险（工程代号「打个毛线 Rope」）· Unity 6000.2.15f1 · TTSDK 6.9.4 · 2026-09-21
已定位根因 已完成修复 待你重开工具窗口复验

一、报错现象

点 TTSDK Unity 调试工具的构建按钮后，Console 依次输出：

build begin, workspace: ...\Unity6000_打个毛线_Rope\tt-minigame
Disable EmscriptenGLX importer path: ...\WebGL\libemscriptenglx_3_1_39.a
Disable EmscriptenGLX importer path: ...\WebGL\libemscriptenglx.a
Disable EmscriptenGLX importer path: ...\WebGL\libemscriptenglx_2021.a
EmscriptenGLX plugin not supported for current Unity version
exception occurred during BuildPlayer: Failed to activate emscripten glx
build failed, see bellow logs for detail.

Editor.log（%LOCALAPPDATA%\Unity\Editor\Editor.log）里给出了准确位置：

Exception: Failed to activate emscripten glx
  at TTSDKBase.Tool.BuildPlatformWebGL.InitializeBeforeBuildPlayer (BuildContext) [0x00046]
  at TTSDKBase.Tool.Builder.DoBuild (BuildContext, BuildStatus) [0x00120]

  ← TTSDKBase.Tool.NativePluginManager:SetEmscriptenGlxCompatibility (IReadOnlyList<PluginImporter>, ...)
  ← TTSDKBase.Tool.NativePluginManager:ProcessEmscriptenGlxLib (bool)
构建中断在最前面，连包体都没产出 —— 失败发生在 InitializeBeforeBuildPlayer（构建前置准备阶段）， 不是打包到一半失败，所以 tt-minigame 目录里不会有新产物。

二、根因

① GLX 没有匹配当前 Unity 版本的库（直接原因）

TTSDK 只随包提供固定几版预编译的 GLX 静态库，按引擎版本二选一：

库文件对应引擎版本
libemscriptenglx_2021.aUnity 2021
libemscriptenglx_3_1_39.aUnity 2022 / emscripten 3.1.39
libemscriptenglx.a默认档

当前 Unity 版本（6000.2.15f1）不在这份名单里。工具用 GetEmscriptenGlxLibNameForCurrentVersion() 按引擎版本挑库 → 一个都挑不中 → 逐个 Disable 掉全部候选 → 不做降级、直接抛异常，构建就此中断。

GLX 是可选项，关掉是安全的。它是 TTSDK 6.9.2 才上线的加速功能，且：
  • TTSDK.jslib / JSB.jslib / TTUNBridge.jslib 里没有任何 glx 硬引用（已逐个查过）
  • 模板 JS 里也是条件判断：if (GL.isInGLXMode?.() && !!Module['_glx_init'])，库不在就自动跳过
  • 关掉只是少一层字节的 GL 转发优化，不影响玩法、不影响上架

② isWebGL2 = 0 与 Unity 6 冲突（紧随其后的第二个坑）

Unity 6 起只支持 WebGL 2.0，WebGL 1 已被移除。官方文档原文：

"Unity no longer provides support for WebGL 1 in builds created with the Auto Graphics API option."

而 TTSDK 会按 StarkBuilderSetting.isWebGL2 去覆盖 PlayerSettings 的 Graphics API。 设成 0 会让它把 WebGL 平台压回 WebGL 1.0 —— 在 Unity 6 上不可能构建成功。

这个坑和常见的「Incompatible color space」是两回事。那条报错只在 Linear 色彩空间下出现； 本工程 m_ActiveColorSpace: 0 是 Gamma，所以永远看不到那条提示—— 别因为没看到它，就以为 WebGL2 没问题。两项独立，都需要修。

三、修复内容

改的文件：Assets/Editor/StarkBuilderSetting.asset（TTSDK 工具窗口读写的就是它）

字段改前改后原因
enableEmscriptenGlx 10 Unity 6 没有匹配的 GLX 库，开着会让工具抛异常中断构建
isWebGL2 01 Unity 6 只支持 WebGL 2.0，不修会紧接着再失败一次

另外新增一个兜底工具，把编辑器内存里的那份设置也钉成正确值 （工具窗口可能缓存旧值，点构建时读的是内存）：

Assets/MyAssets/Editor/RopeTTSDKBuildFix.cs

  • 切回 Unity 后自动跑一次，把上面两个字段写成 0 / 1
  • 菜单手动入口：Tools ▸ 打个毛线 ▸ 修复 TTSDK 构建设置（Unity 6）
  • 另有 检查 TTSDK 构建设置 可打印当前值并标出是否合规
  • 日志标签 [TTSDK构建修复]，兼容 bool / int 两种字段类型，逐项 try/catch

四、你要做的事（1 步）

1
切回 Unity → 等编译完 → 关闭并重新打开 TTSDK 工具窗口 → 再点构建。
必须重开窗口：工具窗口里那个「是否启用 EmscriptenGLX」复选框是它的内存值， 不重开可能仍按旧值（勾选状态）构建，等于没改。重开后复选框应变成未勾选。

构建前建议先在 Console 搜 [TTSDK构建修复]，正常会看到：

[TTSDK构建修复] 已修正 2 项设置（自动）
[TTSDK构建修复] 现在可以回到 TTSDK 工具窗口重新点击构建。

或者手动跑一次 Tools ▸ 打个毛线 ▸ 检查 TTSDK 构建设置 核对，应输出：

[TTSDK构建修复] ===== TTSDK 构建设置 =====
[TTSDK构建修复]   enableEmscriptenGlx = 0  [OK]  (Unity 6 没有匹配的 GLX 库)
[TTSDK构建修复]   isWebGL2 = 1  [OK]  (Unity 6 只支持 WebGL 2.0)

五、回滚方法

备份在：…\Unity6000_打个毛线_Rope\_RopeGlx_Backup_20260921_103834\StarkBuilderSetting.asset

覆盖回去即可恢复原状（两个字段都回 1 / 0）。 但只有在 TTSDK 升级到带 Unity 6 GLX 库的版本后，回滚才有意义 —— 在当前 TTSDK 6.9.4 上恢复 enableEmscriptenGlx: 1 会重新触发这次的报错。
